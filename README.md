# 基于 MFCC 与 VQ 的多特征融合声音锁原型系统

SRDP 项目：在普通电脑和小样本自采录音条件下，使用 **MFCC、LBG-VQ 和 DTW** 实现用户注册、声音验证与实验结果展示。主程序是 Python + PySide6 桌面应用，适合课程展示、项目答辩和组内协作。

系统以“芝麻开门”为固定口令，通过声纹匹配和口令声学模板匹配共同判断是否接受。本项目是软件原型，未接入实体门锁。

**结项范围（2026-11-01）**：算法优化阶段已结束，保留现有 MFCC + VQ、MFCC + DTW、阈值、裁剪和四条合格录音注册规则。接下来只整理交付说明和完成真实设备验收，不重训、不开展新算法实验。本文的运行说明与设备清单为当前口径；旧计划和实验记录按各自版本、数据及协议解释。

## 方法与功能

```text
麦克风 / WAV
     ↓
语音质量检查与预处理
     ↓
特征提取与归一化
     ├─ MFCC + LBG-VQ：声纹匹配
     └─ 特征序列 + DTW：口令模板匹配
                    ↓
             接受 / 拒绝与分数
```

- **MFCC**：提取语音频谱特征，作为声纹与口令比较的输入。
- **LBG-VQ**：建立说话人码本，计算待测语音与用户模型的距离。
- **DTW**：对齐不同语速的特征序列，比较待测语音与注册口令模板的相似度。
- **注册质量检查**：给出静音、有效活动时长、近满幅和短促声音等提示，支持逐条移除与重录。
- **可追溯验证**：记录录音路径、模型指纹、距离/阈值及诊断信息，支持后续复核。
- **对比实验**：提供特征组合、码本大小、DTW 策略、阈值校准及融合方案的离线实验入口。

**口令分支比较声音相似度，不将语音识别成文字。** 因此，“口令模板匹配通过”不能直接解释为识别出了正确文字；该分数也会受到音色、语速和发音影响。

当前默认声纹和口令分支均使用 12 维 MFCC；提取的 Delta 和谱特征用于已有离线对照，不能据此声称当前 App 已部署多特征融合。

### 真实设备验收清单（用户执行，当前均待确认）

在实际答辩电脑、麦克风和普通说话距离下进行，固定默认配置和目标账号；四类测试用注册后新录音，预先写明实际说话人、口令原文及每类次数（建议各 3 次），不挑选成功样本替代完整记录。

- [ ] **启动与注册**：按启动命令打开 App；三条合格录音时不能注册，四条后可保存并自动返回验证页；不合格录音不计数，移除后可补录。
- [ ] **本人正确口令**：目标本人说“芝麻开门”，记录实际通过数与误拒数。
- [ ] **本人相似错误口令**：目标本人说预先写定的错误口令，例如“芝麻关门”，记录实际误通过数。
- [ ] **他人正确口令**：另一人对同一目标账号说“芝麻开门”，记录实际误通过数。
- [ ] **他人错误口令**：另一人对同一目标账号说预定错误口令，记录实际误通过数。
- [ ] **结果与重启恢复**：显示本次判定、声纹/口令分数和拒绝原因；关闭重开后能加载同一用户和验证记录。
- [ ] **取消**：注册录音、注册计算及验证中分别尝试取消；等待当前步骤结束，无新增本次模型/验证结果，麦克风能重新使用，关闭窗口正常。
- [ ] **录音异常恢复**：静音注册不计数；静音验证显示输入拒绝；麦克风不可用时给出失败提示，不沿用上次成功结果；恢复设备后可再次录音。

每类通过率＝通过数/该类总数；本人正确口令误拒率＝拒绝数/本人正确总数，其他三类误通过率＝通过数/各类总数。保留 WAV、用户模型及模型指纹、口令标签、结果导出和设备信息；App 只保留最近 20 条验证记录，较多记录应及时导出，并另存对应原始 WAV，CSV 导出不等于保存音频。验收记录不混入原 99 条正式数据。

功能检查关注能否完成流程、正确显示本次计算结果并恢复操作；认证接受/拒绝与预期不符必须如实统计。若仍误拒或误通过，应报告原型局限，不能为通过验收改阈值或删失败记录。上述少量测试不支持总体安全性结论。

### 命令行单条推理

