# 成员 4：非注册用户与回放风险样本负责人

## 角色定位

本角色负责非注册用户冒充样本和手机回放风险样本。这个角色的输出用于证明声音锁不是普通口令识别，而是同时判断“是不是注册用户”和“口令是否正确”。

这部分对结题答辩很关键，因为老师最容易问：

- 不是本人说正确口令会不会通过？
- 播放录音会不会通过？
- 你们有没有考虑声音锁安全风险？

## 负责样本数量

本角色目标交付 57 条正式合格样本：

| 类别 | 数量 |
|---|---:|
| 非注册用户冒充样本 | 37 |
| 注册用户手机回放样本 | 20 |
| 合计 | 57 |

## 非注册用户冒充样本

当前已有 U01 的 3 条非注册样本。结题目标是至少 5 名非注册用户，即 U01-U05。

需要新增：

```text
37 条非注册用户样本
```

推荐分配：

- U02：8 条；
- U03：8 条；
- U04：8 条；
- U05：8 条；
- U01：补 5 条。

每个非注册用户尽量覆盖：

| 条件 | 数量 |
|---|---:|
| 正常距离电脑麦克风 | 3 |
| 手机麦克风 | 2 |
| 远距离 | 2 |
| 背景噪声 | 1 |

非注册用户全部说正确口令：

```text
芝麻开门
```

metadata：

```text
speaker_id = U02 / U03 / U04 / U05
split = impostor
expected_decision = REJECT
trial_type = impostor
is_replay = false
```

## 手机回放样本

每个注册用户 5 条，共 20 条：

```text
4 名注册用户 × 5 条 = 20 条
```

采集方法：

1. 找到该注册用户之前录过的正确口令音频。
2. 用手机外放播放这段音频。
3. 用电脑麦克风或演示设备麦克风重新录入。
4. 录出来的新 WAV 作为回放测试样本。

metadata：

```text
speaker_id = S01_replay / S02_replay / S03_replay / S04_replay
split = replay
expected_decision = REJECT
trial_type = replay
is_replay = true
device = pc_mic
distance = normal
```

如果代码负责人希望 `speaker_id` 保持原用户，例如 `S01`，则必须在 notes 中写明 replay，并保证 `expected_decision = REJECT`。最终以代码负责人和数据统筹负责人定稿为准。

## 回放样本注意事项

- 不要直接复制原 WAV 当作回放样本。
- 必须真实通过手机外放再录一次。
- 手机音量建议分两档：正常音量和偏大音量。
- 录音环境不要过分安静，保留真实现场效果。
- 不要声称这是成熟防伪，只说“回放风险评估样本”。

## 文件命名建议

非注册用户：

```text
U02/pc_mic_normal_impostor/U02_pc_mic_normal_impostor_001.wav
U03/phone_mic_normal_impostor/U03_phone_mic_normal_impostor_001.wav
```

回放样本：

```text
S01_replay/pc_mic_normal_replay/S01_replay_001.wav
S02_replay/pc_mic_normal_replay/S02_replay_001.wav
```

最终以数据统筹负责人给出的命名模板为准。

## 交付给数据统筹负责人

每批交付时必须包含：

- WAV 文件；
- metadata 行；
- 非注册用户人数统计；
- 回放样本来源说明；
- 发现的问题样本列表。

## 完成标准

本角色完成时，应满足：

- 非注册用户达到至少 5 人；
- 新增非注册样本达到 37 条；
- 回放样本达到 20 条；
- 所有非注册样本 `expected_decision` 都是 `REJECT`；
- 所有回放样本 `is_replay` 都是 `true`；
- 所有样本都能正常播放且路径正确。

## 答辩可用表述

可以交给报告/PPT负责人使用：

> 为了验证声音锁不是单纯识别口令，我们补充了非注册用户说出正确口令的冒充样本；为了展示声音锁面临的安全风险，我们补充了手机播放预录音后的回放测试样本。回放部分只作为风险评估，不声称系统已经具备商用级活体检测能力。
