# 成员 5：报告、PPT 与答辩演示负责人

> **归档说明（2026-11-02）**：下文保留历史分工、采集数量与计划，不代表已交付或当前待办。当前 master 已加入 E 个人验证，v1.0.0 仍是旧双层，ECAPA 未部署。以[README](../../README.md)和[发行验收](../Windows发行准备验收.md)为当前状态；真人结果须如实记录，不改质量门槛或阈值。

## 角色定位

本角色负责把代码结果和数据证据整理成结题报告、PPT、答辩讲稿和演示流程。重点是统一口径，让所有材料都围绕：

- 轻量化；
- 多特征融合；
- 双层验证；
- 一体化原型。

不要把项目讲成商用级声音锁，不要把项目讲成深度学习声纹系统。

## 负责范围

- 结题报告文字整理。
- PPT 页面结构和图表选择。
- 答辩讲稿。
- 现场演示流程。
- 常见问题回答。
- 从代码负责人处接收最终指标，并写成材料。

## 不负责范围

- 不自行修改实验指标。
- 不虚构尚未运行的结果。
- 不把回放样本写成成熟活体检测。
- 不把 MATLAB 前端写成结题正式核心。

## 报告主线

报告建议按以下主线写：

1. 项目背景：声音锁需要同时验证身份和口令。
2. 项目定位：小样本、自采数据、普通 PC、轻量化可解释原型。
3. 系统结构：
   - 音频采集；
   - 预处理；
   - MFCC / Delta / 频谱特征提取；
   - LBG-VQ 说话人分支；
   - DTW 口令分支；
   - 当前双门槛判定，另列历史分数融合实验（未部署）；
   - ACCEPT / REJECT 输出。
4. 数据集：
   - 原始 99 条；
   - 现场验收另存；跨设备、距离、低质量、非注册及回放扩充仅按实际交付列出，不把计划写成成果；
   - 最终样本总数；
   - metadata 字段说明。
5. 实验设计：
   - 特征组合对比；
   - codebook size 对比；
   - DTW 策略对比；
   - 阈值策略对比；
   - 融合策略对比；
   - 不同数据场景对比。
6. 实验结果：
   - 各自协议下的总体判定正确率，区分自动识别、指定账号回归和现场用户；
   - 正常用户通过率；
   - False Reject；
   - False Accept；
   - 错误口令拒识率；
   - 非注册用户拒识率；
   - 回放未完成正式评估，不填写无证据的拒识或风险提示率。
7. Python 一体化演示系统。
8. 局限性和未来工作。

## PPT 建议结构

建议 12-14 页：

1. 封面：项目名称、成员、指导教师。
2. 问题定义：声音锁不是普通语音识别。
3. 项目定位：轻量化、可解释、可复现、可演示。
4. 系统总体架构。
5. 关键算法：MFCC + LBG-VQ。
6. 关键算法：多模板 DTW 口令验证。
7. 多特征和融合离线对比，标明候选未部署及负结果。
8. 数据集设计与实际交付样本，区别历史计划。
9. 实验矩阵。
10. 实验结果对比。
11. Python 一体化演示界面。
12. 现场演示流程。
13. 局限性与改进方向。
14. 总结。

## 必须向代码负责人索取的结果

不要自己估算，必须从已有 CSV、固定回归 JSON 或用户真实验收记录追溯；本轮不重新生成历史结果：

- 当前默认配置与保存旧模型版本是什么，哪些候选未部署或失败；
- 总体判定成绩属于哪种协议，不能将 56/63 自动识别成绩当作账号认证准确率；
- 正常用户通过率是多少；
- False Reject 有几条；
- False Accept 有几条；
- 错误口令拒识率是多少；
- 非注册用户拒识率是多少；
- 回放有无真实评估证据，没有则写“未评估”，不填推测比例；
- 哪个配置不能选，原因是什么。

## 现场演示脚本

演示顺序如下，输出按实际计算展示，期望接受/拒绝不等于已通过验收：

1. 打开 Python GUI。
2. 新用户按四条合格录音完成注册并保存，选择目标账号。
3. 本人重新说正确口令，展示实际判定、波形、MFCC 和分数；如误拒应如实说明。
4. 本人说预定相似错误口令，记录实际判定；不能预设口令分支一定拒绝。
5. 另一人对同一账号分别说正确和错误口令，分别记录实际判定，不混成一类。
6. 展示历史记录并重启确认用户、记录恢复；取消与录音异常恢复按 README 清单检查。
7. 回放未列为本次必做演示，不声称 App 自动识别回放或提示风险。

固定 WAV 可用于离线展示备选，但必须说明它使用旧基础模型，不把它当成现场录音或真实设备验收通过的证据。

## 答辩口径

必须坚持：

> 本项目不是商用级声音锁，而是在普通 PC 条件下，采用 MFCC + VQ 和 MFCC + DTW 双门槛构建注册、验证和结果展示原型。多特征与分数融合属于离线对照，不作为当前 App 已提高稳定性的证据。

关于深度学习：

> ECAPA-TDNN、x-vector 等深度模型适合更大规模声纹任务。本项目结题主线强调小样本和轻量化，因此将深度学习作为未来工作，不接入正式系统主线。

关于回放：

> 当前正式数据未完成回放评估，App 没有经过验证的自动回放检测能力；此项只列为系统局限。

关于误拒：

> 固定账号回归已经观察到误拒与误通过；56/63 只属于历史自动识别协议。真实用户结果单独统计，本轮不开展算法研究，不通过现场调参掩盖失败。
