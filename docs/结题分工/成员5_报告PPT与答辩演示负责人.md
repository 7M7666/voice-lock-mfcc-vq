# 成员 5：报告、PPT 与答辩演示负责人

## 角色定位

本角色负责把代码结果和数据证据整理成结题报告、PPT、答辩讲稿和演示流程。重点是统一口径，让所有材料都围绕：

- 轻量化；
- 多特征融合；
- 双层验证；
- 一体化原型。

不要把项目讲成商用级声音锁，不要把项目讲成深度学习声纹系统。

## 负责范围

- 结题报告文字整理。
- PPT 页面结构和图表选择。
- 答辩讲稿。
- 现场演示流程。
- 常见问题回答。
- 从代码负责人处接收最终指标，并写成材料。

## 不负责范围

- 不自行修改实验指标。
- 不虚构尚未运行的结果。
- 不把回放样本写成成熟活体检测。
- 不把 MATLAB 前端写成结题正式核心。

## 报告主线

报告建议按以下主线写：

1. 项目背景：声音锁需要同时验证身份和口令。
2. 项目定位：小样本、自采数据、普通 PC、轻量化可解释原型。
3. 系统结构：
   - 音频采集；
   - 预处理；
   - MFCC / Delta / 频谱特征提取；
   - LBG-VQ 说话人分支；
   - DTW 口令分支；
   - 分数融合；
   - ACCEPT / REJECT 输出。
4. 数据集：
   - 原始 99 条；
   - 新增跨设备、距离、低质量、非注册、回放样本；
   - 最终样本总数；
   - metadata 字段说明。
5. 实验设计：
   - 特征组合对比；
   - codebook size 对比；
   - DTW 策略对比；
   - 阈值策略对比；
   - 融合策略对比；
   - 不同数据场景对比。
6. 实验结果：
   - 总体准确率；
   - 正常用户通过率；
   - False Reject；
   - False Accept；
   - 错误口令拒识率；
   - 非注册用户拒识率；
   - 回放样本拒识或风险提示率。
7. Python 一体化演示系统。
8. 局限性和未来工作。

## PPT 建议结构

建议 12-14 页：

1. 封面：项目名称、成员、指导教师。
2. 问题定义：声音锁不是普通语音识别。
3. 项目定位：轻量化、可解释、可复现、可演示。
4. 系统总体架构。
5. 关键算法：MFCC + LBG-VQ。
6. 关键算法：多模板 DTW 口令验证。
7. 多特征融合和分数融合。
8. 数据集设计与新增样本。
9. 实验矩阵。
10. 实验结果对比。
11. Python 一体化演示界面。
12. 现场演示流程。
13. 局限性与改进方向。
14. 总结。

## 现场演示脚本

演示顺序建议：

1. 打开 Python GUI。
2. 现场录一条注册用户正确口令，展示波形和 MFCC。
3. 点击验证，输出 `ACCEPT`。
4. 换错误口令，输出 `REJECT`，展示口令分数超过阈值。
5. 换非注册用户说正确口令，输出 `REJECT`，展示声纹分数不通过。
6. 展示回放样本，输出 `REJECT` 或风险提示。
7. 打开历史记录，说明系统保存最近验证结果和耗时。

如果现场环境不稳定，优先使用固定演示样例，但讲清楚后端可以处理现场录音。

## 答辩口径

必须坚持：

> 本项目不是商用级声音锁，而是在小样本、自采数据和普通 PC 条件下，采用 MFCC、VQ、DTW、阈值校准和分数融合等轻量方法，构建可解释、可复现、可现场演示的声音锁原型系统。

关于深度学习：

> ECAPA-TDNN、x-vector 等深度模型适合更大规模声纹任务。本项目结题主线强调小样本和轻量化，因此将深度学习作为未来工作，不接入正式系统主线。

关于回放：

> 回放样本用于展示声音锁存在的安全风险，并测试系统在回放条件下的表现。当前系统不声称具备成熟的强活体检测能力。

关于误拒：

> 当前主要问题是正常用户误拒，不是误接受。后续优化以安全优先为前提，先保持 False Accept 接近 0，再降低 False Reject。
