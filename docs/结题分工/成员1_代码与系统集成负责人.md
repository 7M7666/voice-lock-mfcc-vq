# 成员 1：代码与系统集成负责人

> **归档说明（2026-11-02）**：下文保留历史分工、采集数量与计划，不代表已交付或当前待办。当前 master 已加入 E 个人验证，v1.0.0 仍是旧双层，ECAPA 未部署。以[README](../../README.md)和[发行验收](../Windows发行准备验收.md)为当前状态；真人结果须如实记录，不改质量门槛或阈值。

## 角色定位

本角色负责结题阶段的代码主线、实验复现和 Python 一体化演示系统。所有正式算法改动、实验命令、结果表生成和演示程序集成，统一由本角色把关。

项目主线保持为：

> MFCC + LBG-VQ 负责说话人验证，多模板 DTW 负责口令验证，分数融合负责最终 ACCEPT / REJECT 判定。

不要把正式系统改成深度学习声纹系统，不要把 MATLAB 前端继续作为结题正式展示核心。

## 负责范围

- 维护 `code/python/srdp.py` 的正式识别 pipeline。
- 接入或完善 PySide6 一体化桌面界面。
- 兼容新增 metadata 字段：`device`、`distance`、`trial_type`、`is_replay`。
- 在新数据收齐后重跑：
  - `pipeline`
  - `experiments`
  - `dtw-experiments`
  - `fusion-experiments`
- 输出最终结题用结果表、图表和演示样例。
- 给报告/PPT负责人提供准确指标，不允许口头估计。

## 不负责范围

- 不负责大批量录音采集。
- 不负责单独撰写完整结题报告。
- 不负责随意重写旧工程结构。
- 不负责引入 ECAPA-TDNN、x-vector、端到端 TD-SV 等深度学习主线。

## 必须交付

1. 可运行的 Python 一体化演示界面。
2. 新数据兼容后的 metadata 读取逻辑。
3. 最终实验结果表：
   - `results/tables/experiment_matrix.csv`
   - `results/tables/dtw_strategy_matrix.csv`
   - `results/tables/fusion_matrix.csv`
   - `results/tables/voice_lock_metrics.csv`
4. 最终演示用识别结果：
   - 至少 1 条正常通过样本；
   - 至少 1 条错误口令拒绝样本；
   - 至少 1 条非注册用户拒绝样本；
   - 至少 1 条回放风险样本。
5. 给报告/PPT负责人整理一份“最终指标说明”，包括：
   - 总体准确率；
   - 正常用户通过率；
   - False Reject 数量；
   - False Accept 数量；
   - 错误口令拒识率；
   - 非注册用户拒识率；
   - 回放样本拒识或风险提示率。

## Python GUI 功能清单

界面至少包含以下功能：

- 用户注册：
  - 选择已有用户；
  - 新建临时用户；
  - 现场录入 3-5 条注册口令；
  - 默认只用于当前演示会话。
- 现场验证：
  - 录入一条测试语音；
  - 立即输出 `ACCEPT` 或 `REJECT`；
  - 显示耗时。
- 波形展示：
  - 展示现场录音波形；
  - 用于证明不是只读固定 CSV。
- MFCC 展示：
  - 展示当前录音的 MFCC 热力图；
  - 用于解释特征提取。
- 分数展示：
  - 声纹分数；
  - 口令分数；
  - 融合分数；
  - 对应阈值。
- 拒绝原因：
  - 声纹距离超过阈值；
  - 口令 DTW 距离超过阈值；
  - 疑似回放或低质量风险样本。
- 历史记录：
  - 最近若干次验证结果；
  - 音频路径；
  - 判定结果；
  - 耗时。

## 数据字段兼容要求

新增 metadata 字段为可选字段，旧数据不能坏。

建议字段取值：

```text
device: pc_mic / phone_mic / headset_mic
distance: near / normal / far
trial_type: normal / wrong_passphrase / low_volume / noise / fast / slow / impostor / replay
is_replay: true / false
```

如果旧数据没有这些字段，代码应按空字符串或默认值处理。

## 和数据组的交接

数据负责人交付后，先检查：

- CSV 是否能被 `DictReader` 正常读取；
- `file_path` 是否全部存在；
- WAV 是否能被 `librosa.load` 正常读取；
- `split` 是否只使用约定值；
- `expected_decision` 是否正确；
- 回放样本是否标为 `REJECT`；
- 非注册用户样本是否标为 `REJECT`。

不合格样本退回数据负责人，不在代码里硬兼容错误命名。

## 最终验收标准

完成时必须能做到：

- 一键跑通正式 pipeline。
- GUI 能完成现场录音和现场验证。
- 新数据能进入实验矩阵。
- 报告中的所有指标都能追溯到 CSV。
- 最终安全优先配置保持 False Accept 接近 0。

## 风险提醒

- 不要为了提高总体准确率选择会明显增加 False Accept 的配置。
- 不要把回放样本拒绝写成“成熟活体检测”。
- 不要把临时演示录音自动写入正式实验数据。
- 不要在报告中写尚未运行过的指标。
