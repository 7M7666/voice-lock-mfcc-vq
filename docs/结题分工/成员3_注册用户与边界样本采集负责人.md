# 成员 3：注册用户与边界样本采集负责人

> **结项状态（2026-11-01）**：下文 128 条新增及跨设备、距离、边界矩阵保留为历史计划，不是当前必做项，不作为已完成数据。算法与四条合格录音注册规则冻结；实际设备测试由用户按[README 清单](../../README.md#真实设备验收清单用户执行当前均待确认)执行，保留全部成功与失败结果，不据测试结果继续调参或改注册规则。

## 角色定位

本角色负责 4 名注册用户的新增录音采集，重点补足正确口令在跨设备、距离变化和低质量边界条件下的样本，同时采集注册用户错误口令样本。

这一部分直接决定系统能不能解释“降低正常用户误拒”和“复杂声学环境下仍可演示”。

## 负责样本数量

本角色目标交付 128 条正式合格样本。

每个注册用户新增 32 条，4 名注册用户共：

```text
4 人 × 32 条 = 128 条
```

每人结构如下：

| 类别 | 每人数量 | 4 人合计 |
|---|---:|---:|
| 正确口令，跨设备/距离 | 18 | 72 |
| 正确口令，边界样本 | 8 | 32 |
| 错误口令 | 6 | 24 |
| 合计 | 32 | 128 |

## 正确口令跨设备/距离样本

每个注册用户录 18 条：

```text
3 种设备 × 3 种距离 × 2 次 = 18 条
```

设备：

- `pc_mic`
- `phone_mic`
- `headset_mic`

距离：

- `near`
- `normal`
- `far`

口令统一为：

```text
芝麻开门
```

metadata：

```text
split = test
expected_decision = 对应注册用户，例如 S01
trial_type = normal
is_replay = false
```

## 正确口令边界样本

每个注册用户录 8 条：

| 类型 | 数量 |
|---|---:|
| 低音量 | 2 |
| 背景噪声 | 2 |
| 语速偏快 | 2 |
| 语速偏慢 | 2 |

口令仍为：

```text
芝麻开门
```

metadata：

```text
split = test
expected_decision = 对应注册用户，例如 S01
device = pc_mic 或实际设备
distance = normal
trial_type = low_volume / noise / fast / slow
is_replay = false
```

## 错误口令样本

每个注册用户录 6 条：

```text
3 种设备 × 2 次 = 6 条
```

错误口令固定使用 2-3 种，不要每个人随便编。

推荐错误口令：

```text
芝麻关门
打开门锁
声音解锁
```

metadata：

```text
split = wrong_passphrase
expected_decision = REJECT
trial_type = wrong_passphrase
is_replay = false
```

## 录音要求

- 每条音频尽量控制在 2-4 秒。
- 录音前后保留少量自然空白，不要刚按下就立刻说。
- 不要剪辑音频。
- 不要后期降噪。
- 不要把一次失败录音改名当作成功样本。
- 每种条件下至少听一遍，明显截断或爆音要重录。

## 环境建议

优先保持和已有数据一致：

- 宿舍；
- 走廊；
- 实验室。

如果无法覆盖三类环境，也至少保证 `environment` 字段真实填写，不要乱填。

## 文件命名建议

示例：

```text
S01/pc_mic_near_normal/S01_pc_mic_near_normal_001.wav
S01/pc_mic_far_normal/S01_pc_mic_far_normal_001.wav
S01/headset_mic_normal_wrong/S01_headset_mic_wrong_001.wav
S01/pc_mic_normal_low_volume/S01_low_volume_001.wav
```

最终以数据统筹负责人给出的命名模板为准。

## 交付给数据统筹负责人

每批交付时附上：

- WAV 文件；
- 对应 metadata 行；
- 每个用户的数量统计；
- 坏样本说明。

不要只交音频不交 metadata。

## 完成标准

本角色完成时，应满足：

- S01-S04 每人新增 32 条合格样本；
- 正确口令跨设备/距离样本完整；
- 边界样本完整；
- 错误口令样本完整；
- 所有样本都能在 metadata 中找到；
- 所有 `expected_decision` 标注正确。

## 风险提醒

- 这部分不是为了让训练集变大，而是为了测试系统稳定性。
- 不要把新增正常样本全部放入 `train`。
- 如果某个用户录音状态明显不稳定，要记录在 notes 中，方便解释 False Reject。
