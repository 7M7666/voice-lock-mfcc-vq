# 成员 2：数据统筹与标注负责人

> **归档说明（2026-11-02）**：下文保留历史分工、采集数量与计划，不代表已交付或当前待办。当前 master 已加入 E 个人验证，v1.0.0 仍是旧双层，ECAPA 未部署。以[README](../../README.md)和[发行验收](../Windows发行准备验收.md)为当前状态；真人结果须如实记录，不改质量门槛或阈值。

## 角色定位

本角色负责结题阶段全部数据采集的组织、命名、metadata 标注和质量检查。目标是一次性把结题需要的数据收齐，避免后面反复补录。

数据集目标不是商用级大规模声纹库，而是能支撑结题报告中的完整实验矩阵：

- 注册用户正常口令；
- 注册用户错误口令；
- 非注册用户冒充；
- 跨设备；
- 距离变化；
- 低质量边界样本；
- 手机回放风险样本。

## 总数据目标

当前已有 99 条 WAV。

结题建议最终达到约 280-320 条 WAV。新增正式合格样本建议为 185 条左右，实际录制时建议准备 210 条左右，允许 10%-15% 废片。

新增数据结构如下：

| 类别 | 目标数量 |
|---|---:|
| 注册用户正确口令，跨设备/距离 | 72 |
| 注册用户正确口令，边界样本 | 32 |
| 注册用户错误口令 | 24 |
| 注册用户回放样本 | 20 |
| 非注册用户冒充 | 37 |
| 新增正式合格样本合计 | 185 |

加上现有 99 条后，最终约 284 条，足够支撑结题阶段的实验和答辩。

## 负责范围

- 制作最终采集进度表。
- 统一样本命名规则。
- 维护正式 metadata。
- 分配每位采集执行者的录音任务。
- 每天检查新增 WAV 和 metadata 是否匹配。
- 发现坏样本后安排补录。
- 将最终数据交给代码负责人跑实验。

## 不负责范围

- 不修改算法代码。
- 不改实验结果。
- 不在报告中解释模型效果。
- 不为了凑数量保留明显不合格音频。

## metadata 字段

正式 metadata 必须包含旧字段：

```text
file_path
speaker_id
environment
passphrase
sample_rate_hz
duration_sec
split
expected_decision
notes
```

新增字段：

```text
device
distance
trial_type
is_replay
```

## 字段取值规范

`device` 只能使用：

```text
pc_mic
phone_mic
headset_mic
```

`distance` 只能使用：

```text
near
normal
far
```

`trial_type` 只能使用：

```text
normal
wrong_passphrase
low_volume
noise
fast
slow
impostor
replay
```

`is_replay` 只能使用：

```text
true
false
```

## split 规则

注册用户正确口令：

- 少量用于 `train`；
- 大部分新增样本用于 `test`；
- 不要把所有新增样本都放入训练集。

错误口令：

```text
split = wrong_passphrase
expected_decision = REJECT
```

非注册用户：

```text
split = impostor
expected_decision = REJECT
```

回放样本：

```text
split = replay
expected_decision = REJECT
trial_type = replay
is_replay = true
```

## 命名建议

文件路径建议保留在：

```text
data/demo_audio/srdp_dataset/
```

注册用户：

```text
S01/device_distance_trial/S01_device_distance_trial_001.wav
```

非注册用户：

```text
U02/device_distance_trial/U02_device_distance_trial_001.wav
```

回放样本：

```text
S01_replay/pc_mic_normal_replay/S01_replay_001.wav
```

如果最终代码负责人已有更简单命名方案，以代码负责人定稿为准，但所有人必须统一。

## 每天检查清单

每批录完后检查：

- WAV 文件是否存在；
- 文件名和 metadata 中 `file_path` 是否一致；
- 音频能否正常播放；
- 是否有明显截断、爆音、静音；
- 采样率是否统一为 16000 Hz 或能被 pipeline 重采样；
- `expected_decision` 是否正确；
- 回放和非注册样本是否没有误标为注册用户；
- notes 是否写清楚特殊情况。

## 向代码负责人交付

交付内容：

- 更新后的 `metadata_srdp.csv`；
- 新增 WAV 文件；
- 一份采集统计表，至少包含：
  - 每个 speaker 的样本数；
  - 每个 split 的样本数；
  - 每个 device 的样本数；
  - 每个 distance 的样本数；
  - 每个 trial_type 的样本数。

## 完成标准

本角色完成时，应能回答：

- 现在最终数据集一共有多少条？
- 每类样本各多少条？
- 哪些样本是训练，哪些是测试？
- 回放样本有多少条？
- 非注册用户是否达到 5 人？
- 新增字段有没有空缺或乱写？
- 是否还有需要补录的坏样本？
