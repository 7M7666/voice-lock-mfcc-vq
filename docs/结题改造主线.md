## 项目定位、边界与基线

### 项目定位

项目题目继续保留：

> 基于 MFCC 与 VQ 的多特征融合声音锁原型系统设计与实现

结题阶段不把项目改成深度学习声纹系统，也不改成硬件门锁项目。核心定位是：在小样本、自采数据和普通 PC 条件下，构建一个轻量化、可解释、可复现、可现场演示的声音锁软件原型。

声音锁任务不是普通语音识别，而是文字相关声纹认证。系统必须同时判断两件事：

1. 输入语音是否来自注册用户。
2. 注册用户说出的口令是否正确。

只有身份验证和口令验证都通过，系统才输出 `ACCEPT`；否则输出 `REJECT`。

### 核心边界

- 主线坚持轻量化，不使用深度学习作为正式结题系统主方案。
- `MFCC + LBG-VQ` 继续作为说话人验证主分支，贴合项目题目。
- `DTW` 不再作为唯一算法亮点，而是作为口令验证分支的一部分。
- 深度模型如 ECAPA-TDNN、x-vector、端到端 TD-SV 只作为后续展望或文献对照，不接入主线。
- 不声称系统达到商用级声音锁，也不声称已完成强泛化活体检测。
- 回放攻击只作为风险评估和展示样本纳入，不夸大为成熟防伪模块。

可用于报告和答辩的核心表述：

> 本项目不追求大规模深度模型训练，而是在小样本、自采数据和普通 PC 条件下，采用 MFCC、VQ、DTW、阈值校准和分数融合等轻量方法，构建可解释、可复现、可现场演示的声音锁原型系统。

## 结题方案与验收要求

### 结题主线

结题改造主线按“轻量化多模块系统”推进：

1. 说话人分支：保留 `MFCC + LBG-VQ`，补充分用户阈值和不同 codebook size 对比。
2. 口令分支：将单模板 DTW 升级为多模板 DTW，并尝试约束 DTW 或加权 DTW。
3. 多特征实验：比较 `MFCC`、`MFCC + Delta`、`全部 31 维特征` 的效果。
4. 分数融合：将声纹距离、口令 DTW 距离和必要的音频质量指标转成可比较分数，再做规则式融合。
5. 一体化界面：用 Python 桌面界面替代正式展示中的 MATLAB 前端，实现现场注册和现场验证。
6. 数据扩充：补充非注册用户、跨设备、远距离、低质量边界样本和手机回放样本。
7. 报告统一：所有材料都围绕轻量化、多特征、双层验证、一体化原型这四个关键词展开。

### 实验矩阵

结题报告至少保留以下对比矩阵，避免只报告单一最佳结果：

| 对比目标 | 实验组 |
|---|---|
| 特征组合 | `MFCC`、`MFCC + Delta`、`全部 31 维特征` |
| VQ 码本大小 | `8`、`16`、`32` |
| DTW 策略 | 单模板 DTW、多模板 DTW、约束 DTW |
| 阈值策略 | 全局阈值、分用户阈值 |
| 决策策略 | 仅声纹、声纹 + 口令、分数融合 |
| 数据场景 | 正常口令、错误口令、非注册用户、回放样本 |

每组实验至少报告：

- 总体准确率
- 正常用户通过率
- False Reject 数量
- False Accept 数量
- 错误口令拒识率
- 非注册用户拒识率
- 回放样本拒识或风险提示率
- 混淆矩阵

优化优先级是安全优先：先保持误接受接近 0，再降低正常用户误拒。

### GUI 要求

结题正式展示应以 Python 一体化桌面界面为主，推荐 PySide6。

界面至少包含：

- 用户注册：选择用户或新建用户，现场录入 3-5 条注册口令。
- 现场验证：录入一条测试语音，立即输出 `ACCEPT` 或 `REJECT`。
- 波形展示：证明使用现场真实录音。
- MFCC 展示：帮助解释特征提取过程。
- 分数展示：显示声纹分数、口令分数、融合分数和阈值。
- 拒绝原因：例如“声纹距离超过阈值”“口令 DTW 距离超过阈值”“疑似回放风险样本”。
- 历史记录：展示最近若干次验证结果和耗时。

现场录入默认只用于当前演示会话，也可以提供“一键保存为新样本”入口。保存入口不能自动污染正式实验数据，必须让用户明确确认。

### 现场注册演示保障

答辩现场如果老师希望临时注册，应把“老师现场注册”作为加分演示，而不是唯一演示路径。正式演示仍应先用固定样本跑通完整闭环，确保注册用户正确口令通过、错误口令拒绝、非注册用户拒绝和回放风险样本展示都可稳定完成。

推荐现场流程：

1. 先用固定样本演示完整流程，证明系统主线可复现。
2. 再邀请老师作为临时用户注册，说明现场注册受麦克风和环境噪声影响，系统会先做质量检查。
3. 老师连续念固定口令“芝麻开门”5 次。
4. 系统逐条显示波形、MFCC 和质量状态；静音、截断、爆音、音量过低或质量分过低的录音要求重录。
5. 从 5 条注册音频中选择质量较好的 3-5 条建立临时会话模型，明显离群的注册样本不进入模型。
6. 老师再念一次正确口令，系统输出 `ACCEPT`。
7. 老师或同学念错误口令，系统输出 `REJECT`，并展示口令分数或 DTW 距离超过阈值。
8. 同学冒充老师念正确口令，系统输出 `REJECT`，并展示声纹分支未通过。

现场注册功能应有以下保护栏：

- 注册音频必须检查时长、能量、静音、削波、SNR 或 `quality_score`。
- 质量不合格的音频不进入临时模型，而是提示重录。
- 临时注册样本只用于当前演示会话，不自动写入正式实验数据。
- 如果提供保存入口，必须二次确认，并明确区分“演示样本”和“正式实验样本”。
- 现场用户阈值可以根据注册样本内部一致性自适应估计，但不能无限放宽。声纹阈值和口令阈值建议由注册样本间距离估计，并设置安全上限。
- 如果现场环境过吵或录音设备异常，应切回固定样本演示，不把单次现场失败解释为算法整体失败。

可用于现场说明的表述：

> 现场注册会受到麦克风、环境噪声和说话稳定性的影响，所以系统会先做录音质量检查。质量不合格的样本不会进入注册模板，需要重录。这也是声音锁系统实际使用时必须具备的环节。

### 算法审查与 GitHub 参考（2026-10-29）

以下为实现前的审查和隔离试验记录；随后实现及实验结果见下方“已实现的算法改动与结果”。历史正式模型、特征和结果表保留。

1. **确定的LBG实现问题**：`lloyd_refine()` 把上一轮失真初始化为正无穷，然后比较 `abs(last_distortion-distortion) <= tol*max(last_distortion,1)`。第一轮会变成 `inf <= inf` 并提前返回，各级LBG分裂只细化一次。已用6点、2中心样例复现：当前返回 `[0,7.6]`，充分迭代应为约 `[1.6667,11]`。应先增加回归验证，修复收敛判断，再重训并重校准，不把修复本身包装成新算法。
2. **隔离结果并非提升**：仅在内存中为该判断添加有限值检查，保持MFCC/cb16、全部特征口令DTW及原阈值估计规则，在原36条训练/63条评估上复核。结果52/63（82.5%），正常通过13/24（54.2%），误拒11、误接受0；对应旧推荐候选为57/63、18/24、误拒6、误接受0。四名用户训练距离均下降，声纹阈值也下降。结果支持优先研究训练内拟合与阈值校准问题，不支持“充分聚类必然提升识别率”。输出保存在 `tmp/algorithm_audit_w6aa35po/`，包括 `summary.json`、`metrics.csv`、`recognition.csv`、`model.npz`；未生成图，临时命令中的图输出提示不代表图已生成。
3. **阈值应使用留出的整条录音校准**：现有声纹阈值使用参与码本训练的录音距离；现场注册还有经验倍数。候选改法是在训练录音内部按整条音频留一建模、估计正常分数，并用其他注册用户作有限冒充对照；不得按帧随机切分造成泄漏。现有评估集已经参与历史选型，不能称为全新独立测试。
4. **融合存在冗余配置**：声纹/口令均要求分数不超过1时，质量权重0、融合阈值1的凸加权平均不会新增拒识条件。现有硬声纹门槛也决定融合无法挽回已被声纹分支提前拒绝的正常样本。应在校准集比较双门槛、有效的融合规则及明确的安全边界，保留能解释实际判定变化的方案。
5. **预处理与口令候选**：当前能量裁剪只截去首尾，纯静音会原样返回；应显式识别无有效语音，比较帧级VAD。DTW已实现窗口与惩罚，后续应检查路径可视化、局部斜率/路径长度约束、动态特征或代表模板；不能把已有功能当新成果。CMN/CMVN可作单独消融，但可能同时去掉说话人信息，不预设一定提升。
6. **App候选**：注册录音的 `sd.wait()`、质量分析、注册建模和用户验证目前仍同步运行；可参考官方录音示例改用音频回调/队列和Qt工作线程，增加设备选择、录音电平/进度、取消与结束状态，保持界面响应。

**引入互补信息的依据与开发顺序**：在第一组失败后，只先检查注册侧基频：lwl2四条中位基频约149–159 Hz，lyh2约214–252 Hz。新增原始裁剪波形上的`librosa.yin`，固定65–400 Hz、1024采样帧和原帧移，仅保留原能量活动且周期相关系数≥0.6的帧，至少8帧才计算中位log2基频；没有新依赖或深度模型。先试注册留一绝对基频波动门槛，发现lyh2正确第3条约279.6 Hz超出该门槛；这组失败保留，未据此放宽其绝对阈值。

之后另立**探索性**相对基频族：比较查询log2基频到两人注册均值的绝对偏差，目标偏差/另一人偏差≤1才保留。它用两人的注册中心形成固定比较，不用查询拟合基频阈值，也不改变原声纹门槛；本质上是已知两账户间的辅助身份信息，不能独立承担开放集身份认证。相对规则是在看过绝对门槛失败后提出，必须承认这一开发适应过程，不能说全部方法在看数据前已预注册。最后补充固定Delta阈值消融，显式展示由最佳单流选择得到的规则，不把事后命名变成预设独立验证。

## 数据扩充与协作安排

### 数据扩充

新增数据不只追求总量，而要补当前短板：

- 非注册用户从 1 人扩到至少 5 人。
- 保留 4 名注册用户，每人继续补充正确口令、错误口令和边界样本。
- 新增不同设备录音，例如电脑麦克风、手机麦克风、耳机麦克风。
- 新增距离变化样本，例如近距离、正常距离、远距离。
- 新增低质量边界样本，例如低音量、背景噪声、语速变化。
- 新增手机播放预录音的回放测试样本。

结题数据集目标不是做大规模商用声纹库，而是让报告覆盖完整场景。建议最终数据量达到 **280-320 条 WAV**。当前已有 99 条，因此新增正式合格样本建议约 **185 条**。实际录制时建议准备 **210 条左右**，预留 10%-15% 废片空间。

新增数据建议按以下矩阵一次性收齐：

| 类别 | 数量 |
|---|---:|
| 注册用户正确口令，跨设备/距离 | 4 人 × 3 设备 × 3 距离 × 2 次 = 72 |
| 注册用户正确口令，边界样本 | 4 人 × 4 类型 × 2 次 = 32 |
| 注册用户错误口令 | 4 人 × 3 设备 × 2 次 = 24 |
| 注册用户回放样本 | 4 人 × 5 次 = 20 |
| 非注册用户冒充 | 最终 5 人 × 8 次 = 40，已有 U01 3 条，因此新增 37 |
| **新增正式样本合计** | **185** |

这样加上原有 99 条，最终约 284 条 WAV，对结题阶段较完整，也不会把项目膨胀成大规模声纹库。

#### 注册用户采集要求

保留现有 4 名注册用户。每个注册用户新增 37 条：

1. 正确口令正常样本：18 条。
   - `电脑麦克风 / 手机麦克风 / 耳机麦克风` × `近距离 / 正常距离 / 远距离` × 2 次。
   - 口令统一为“芝麻开门”。
   - `split = test`，`expected_decision = 对应注册用户`。
2. 正确口令边界样本：8 条。
   - `低音量` 2 条。
   - `背景噪声` 2 条。
   - `语速偏快` 2 条。
   - `语速偏慢` 2 条。
   - 口令仍为“芝麻开门”。
   - `split = test`，`expected_decision = 对应注册用户`。
3. 错误口令：6 条。
   - 3 种设备 × 2 次。
   - 错误口令固定 2-3 个即可，例如“芝麻关门”“打开门锁”“声音解锁”。
   - `split = wrong_passphrase`，`expected_decision = REJECT`。
4. 回放样本：5 条。
   - 用手机播放该用户之前录好的正确口令，再用电脑麦克风重新录入。
   - 必须真实外放再录一次，不能直接复制原 WAV。
   - `split = replay`，`expected_decision = REJECT`，`is_replay = true`。

#### 非注册用户采集要求

非注册用户至少做到 `U01-U05` 共 5 人。每个非注册用户 8 条：

- 正常距离电脑麦克风 3 条。
- 手机麦克风 2 条。
- 远距离 2 条。
- 背景噪声 1 条。

非注册用户全部说正确口令“芝麻开门”，但 `expected_decision` 必须为 `REJECT`。这类样本用于证明系统不是普通口令识别，而是身份验证和口令验证双重判定。

#### metadata 字段和取值

metadata 可增加以下可选字段：

- `device`
- `distance`
- `trial_type`
- `is_replay`

新增字段必须保持向后兼容。已有 pipeline 能继续读取旧 metadata。

建议取值固定，不要自由发挥：

```text
device: pc_mic / phone_mic / headset_mic
distance: near / normal / far
trial_type: normal / wrong_passphrase / low_volume / noise / fast / slow / impostor / replay
is_replay: true / false
```

旧数据这些字段可以留空。新数据必须尽量填完整，方便后续按设备、距离、边界类型和回放样本分组统计。

#### 采集规则

- 训练集不要无限增加。保持“小样本注册”定位，每个注册用户正式训练样本控制在 3-5 条，或沿用现有 `train`。
- 新增的大部分样本应放入 `test / wrong_passphrase / impostor / replay`，不要把测试场景提前喂给系统。
- 每条音频尽量控制在 2-4 秒，前后保留少量自然空白。
- 不做后期降噪，不剪辑音频，不把失败录音改名当作成功样本。
- 采集前先试录 10 条，跑一次 `features`，确认能读取、SNR 正常、metadata 路径正确，再正式铺开。
- 每批数据交付时同时提交 WAV 和 metadata 行，不允许只交音频。

## 答辩口径

答辩时建议坚持以下说法：

- 当前项目是软件原型，不是商用级产品。
- 复杂声学环境在本项目中先落实为多场景室内录音，并逐步扩展到跨设备、远距离和低质量样本。
- DTW 不是唯一算法，而是口令验证分支；系统还包含 VQ 声纹分支、阈值校准和分数融合。
- 多特征融合必须用实验表证明，不能只说已经提取了很多特征。
- 当前中期主要问题是误拒，不是误接受；后续重点是在保持安全边界的前提下降低 False Reject。
- 回放样本用于展示声音锁安全风险，但不声称已完成强活体防伪。
- 深度学习方法放在未来工作，原因是项目强调轻量化、小样本和普通 PC 可运行。
- 老师现场注册属于可选加分演示，正式答辩仍以固定样本和可复现实验结果为保底；现场注册失败时优先检查录音质量、环境噪声和样本一致性，不把单次现场失败夸大为系统不可用。

可用于总结页的一句话：

> 本项目从单一 MFCC-DTW 演示升级为轻量化多模块声音锁原型：以 VQ 完成身份验证，以多模板 DTW 完成口令验证，以多特征实验和分数融合提升稳定性，并通过 Python 一体化界面实现现场注册、现场验证和可解释展示。
